#+TITLE: NUMA

非一致性内存访问（Non-Uniform Memory Access、NUMA）是一种计算机内存的设计方式，设计上每个 NUMA 口有对应的 CPU 和内存，CPU 访问同 NUMA 上的内存时叫做 Local Access，
访问不同口上的 NUMA 叫做 Remote Access，Local Access 比 Remote Access 速度更快。

参考 [[https://serverfault.com/questions/1062690/latency-of-memory-accesses-via-interconnectors][Latency of memory accesses via interconnectors - Server Fault]] 中的数据：
#+begin_quote
+ The latency of memory access directly connected to the CPU's socket is about 90ns.
+ The latency of memory access connected to other CPU's socket which is connected by UPI to the CPU's socket is about 140ns (so one "hop" of UPI adds about 50ns).
+ The latency of memory access via the considered NUMA interconnect is 370ns (so one "hop" of this interconnect adds about 280ns).
#+end_quote

在现在的计算机中，一个计算机可以有多个 CPU Socket（CPU 插槽），每个插槽上的 CPU 可以有多个，同时每个 CPU 可能又可以开超线程一核当两核用，而 NUMA 可以定义这些 CPU 访问内存时使用的方式是 Local 和 Remote。

在希望通过「绑核」操作来提高程序性能时，一方面可以将程序不同线程绑定到不同的 CPU 核心上，利用「[[id:CE51393A-3B5A-4AC7-B464-7981A4F722D4][局部性原理]]」来提高缓存命中的概率，同时也可以考虑使用一些库按照 NUMA 分布来创建对象，
让线程访问的对象总是在自己的 NUMA 上，避免 Remote Access。

* numactl & numastat
  可以使用 numactl 命令查看节点 numa 情况：
  #+begin_example
    # 查看 NUMA 节点数量、每个节点的 CPU 和内存
    numactl --hardware

    # 示例输出（双节点系统）
    available: 2 nodes (0-1)
    node 0 cpus: 0 1 2 3
    node 0 size: 32123 MB  # 节点 0 内存（约 32GB）
    node 0 free: 28546 MB
    node 1 cpus: 4 5 6 7
    node 1 size: 32127 MB  # 节点 1 内存（约 32GB）
    node 1 free: 29102 MB
    node distances:
    node   0   1
      0:  10  20  # 节点 0 访问自身延迟 10（相对值），访问节点 1 延迟 20
      1:  20  10  # 节点 1 访问自身延迟 10，访问节点 0 延迟20
  #+end_example

  可以看到，不同节点间的访问延迟是不一样的 node distances。可以进一步使用 numastat 查看每个节点的本地分配（numa_hit）、远程分配（numa_miss）：
  #+begin_example
                               node0           node1
    numa_hit            154377699310    132152825520
    numa_miss             6920113185       703415051
    numa_foreign           703415051      6920113185
    interleave_hit             26625           26765
    local_node          153714130881    132149649698
    other_node            7583681609       706590873
  #+end_example

* Socket & NUMA
  核心定义与本质：
  + socket（CPU 插槽）
    + 物理硬件接口，指主板上用于安装物理 CPU 芯片的插槽。
    + 每个 socket 对应一颗独立的物理 CPU，数量决定系统可安装的物理 CPU 最大数量（如“2 路服务器”含 2 个 socket）。
    + 例：2个 socket 的服务器安装 2 颗 8 核 CPU，总核心数 16 核。

  + NUMA node（NUMA 节点）
    + 逻辑资源单元，基于“内存访问延迟一致性”划分的资源组。
    + 包含一组 CPU 核心、核心直接连接的“本地内存”及关联 I/O 设备。
    + 核心目的：优化内存访问效率（同节点内 CPU 访问本地内存延迟低，跨节点访问延迟高）。
    + 例：双 socket 服务器通常对应 2 个 NUMA node，每个 node 含 1 颗 CPU 的核心和其连接的内存。

  典型关系与实例：
  + 多数场景：1个 socket（物理 CPU）对应 1 个 NUMA node（如 2 socket 服务器 → 2 NUMA node）。
  + 特殊场景：1个 socket 对应多个 NUMA node（如 AMD EPYC CPU 内部含多个 Die，每个 Die 为 1 个 node）。

  总结：
  + socket 是物理插槽，对应硬件层面的物理 CPU，决定 CPU 安装数量；
  + NUMA node 是逻辑分组，基于内存访问特性绑定CPU和内存，优化访问效率；
  + 两者通常一一对应，但分属“硬件物理结构”和“逻辑资源管理”层面，作用不同。
